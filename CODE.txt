HALCYON SERVER
================

Yeh file sirf server ka code samjhane ke liye hai.
Folder: server/src
API port 4000 pe chalti hai. MongoDB local hai: mongodb://127.0.0.1:27017/halcyon
Timezone Asia/Kolkata hai. Slots 10:00 se 18:00, 30 minute ke. Last start 17:30.

Request kaise chalti hai
------------------------

1. index.js Express start karta hai aur MongoDB se connect karta hai.
2. URL /api se routes/index.js mein jaati hai.
3. Route controller ko bulati hai.
4. Controller body ya query check karwata hai, phir service function call karta hai.
5. Service MongoDB se padhti ya likhti hai.
6. Agar kahin throw hota hai, errorHandler usko JSON error bana kar bhej deta hai.

Controller patla hai. Asli kaam service aur validation mein hai.


server/src/index.js
-------------------

Yeh entry file hai. npm start isi ko chalata hai: node src/index.js

dotenv .env padhta hai. Wahan teen cheezein hain:
- PORT=4000
- MONGODB_URI=mongodb://127.0.0.1:27017/halcyon
- CLIENT_ORIGIN=http://localhost:3000

Agar env missing ho to code khud yahi default le leta hai.

express() app banata hai.
cors sirf React origin ko allow karta hai, yani localhost:3000.
express.json body padhta hai, limit 20kb hai. Bada body reject ho jata hai.

GET / sirf { name: 'Halcyon API', health: '/api/health' } bhejta hai.
app.use('/api', routes) saari API routes yahan se lagti hain.
Uske baad koi unknown URL 404 JSON deti hai.
errorHandler sabse last middleware hai, taaki throw hua error yahin pakda jaye.

main()
Pehle connectDb, phir app.listen. Console pe "API on http://localhost:4000".
Agar MongoDB nahi chali to catch message print karke process.exit(1).

server/src/middleware/errorHandler.js
-------------------------------------

errorHandler(err, req, res, next)
Agar response pehle hi ja chuka hai to next(err) karke return.

"Something went wrong on our side. Please try again."

server/src/utils/time.js
------------------------

Constants
TIMEZONE = Asia/Kolkata
DAY_OPEN = 10:00, DAY_CLOSE = 18:00
SLOT_MINUTES = 30
WINDOW_DAYS = 60
DAY_OPEN_MINUTES = 600, DAY_CLOSE_MINUTES = 1080

pad(value)
1 ko "01" banata hai.

minutesToTime(total)
630 ko "10:30" banata hai.

timeToMinutes(hhmm)
"10:30" ko 630 banata hai.

buildDaySlots()
10:00 se 18:00 tak 30 minute ke slot banata hai.
Start 10:00, 10:30, ... 17:30. Total 16 slots.
Har slot mein startTime aur endTime hota hai. 17:30 ka end 18:00 hai.

SLOT_STARTS
Un 16 start times ka Set. Baar baar loop na chalana pade.

isSlotStart(value)
"10:30" true. "10:15" ya "18:00" false. 18:00 close hai, start nahi.

endTimeFor(startTime)
Start mein 30 minute jod kar end time deta hai.

kolkataNow(date)
Server UTC pe ho tab bhi India ka aaj ka date aur abhi ke minutes nikalta hai.
Intl Asia/Kolkata use karta hai.
Return: { isoDate: "2026-10-09", minutes: 870 }
minutes raat 12 baje se ab tak ke minute hain. 14:30 ka matlab 870.
Hour 24 ko 0 kar deta hai, kyunki kuch engines midnight ko 24 likhte hain.

isRealDate(iso)
"2026-02-31" false, kyunki February mein 31 nahi hota.
Format YYYY-MM-DD hona chahiye, aur date sach mein exist karni chahiye.

addDaysISO(iso, days)
"2026-10-09" mein 60 din jod kar naya ISO date deta hai.
UTC date use hoti hai taaki timezone se din na khisak jaye.

dateProblem(iso, now)
Khali string matlab date theek hai.
Galat date: "Choose a valid date."
Aaj se pehle: "That date has already passed."
60 din se aage: "You can book up to 60 days ahead."

isPastSlot(date, startTime, now)
Purana din true.
Aane wala din false.
Aaj ka din: agar slot ka start abhi ke minute se pehle ya barabar hai to true.
Matlab jo slot shuru ho chuka hai, woh book nahi hota.

hasEnded(date, endTime, now)
Visit khatam ho gayi ya nahi.
Aaj ke din end time nikal chuka ho to true.
List mein upcoming aur closed alag karne ke liye yeh use hota hai.
Farq: isPastSlot start dekhta hai, hasEnded end dekhta hai.
Chal rahi visit abhi upcoming rehti hai, book nahi ho sakti.

formatPhone(phone)

server/src/utils/reference.js
-----------------------------

makeReference()
crypto.randomBytes(6) se 6 random letters.
Alphabet mein 0, O, 1, I nahi hain, taaki phone pe padhte time ulajhan na ho.
Return "HL-" aur 6 characters, jaise HL-E9NRRC.
Yeh booking ki public id hai. Mongo _id alag hai.


server/src/validation/booking.js
--------------------------------

normalizePhone(input)
Sirf digits nikalta hai.
91 aur 12 digit ho to pehle 2 hata kar 10 digit.
0 se start 11 digit ho to pehla 0 hata deta hai.
10 digit, pehla digit 6, 7, 8, ya 9 hona chahiye.
Galat ho to khali string. Sahi ho to wahi 10 digit.

cleanName(input)
Extra spaces hata kar ek space kar deta hai, trim karta hai.

issueMessage(issue)
Zod ki error ko seedha sentence banati hai.
Type galat ho to "Name is missing or in the wrong format."
Warna Zod ka apna message.

parseBooking(body, now)
Body object na ho to 400 "Send the booking details as JSON."
Phir Zod schema check karta hai:

serviceId    consultation, demo, ya support
date         YYYY-MM-DD, aur dateProblem se past ya 60 din se aage nahi
startTime    HH:MM aur isSlotStart true
customerName 2 se 80 character, letters, space, period, apostrophe, hyphen
email        sahi email, max 120
phone        normalizePhone se 10 digit Indian mobile

safeParse fail ho to har field ka pehla message fields object mein jata hai.
HttpError 400, code INVALID_INPUT, aur fields.
Success pe clean data return:
name clean, email lower case, phone 10 digit.


server/src/validation/queries.js
--------------------------------

parseSlotQuery(query, now)
serviceId getService se milna chahiye, warna 400.
date dateProblem se theek honi chahiye.
Return { service, date }.

optionalEmail(value)
Khali ho to khali string. Galat format ho to 400.
Sahi ho to trim aur lower case.

visitFilters(query)
Optional serviceId, status, date se Mongo filter banata hai.
status sirf confirmed ya cancelled.
date isRealDate se check. Yahan 60 din ki limit nahi, kyunki purani visit bhi list mein dikhni hai.

parseListQuery(query)
Visitor ki list. Email zaroori hai, warna 400 "Enter the email you booked with."
Return { email, ...filters }.
Isi se ek user ko sirf apni appointments milti hain.

wholeNumber(value, fallback, label)
page aur limit ke liye. Khali ho to default. Integer na ho to 400.

parseAdminListQuery(query)
Desk list. Email optional hai.
q search hai. 80 character se lambi ho to 400.
Regex ke special characters escape hote hain, taaki user pattern inject na kare.
Search case-insensitive hai, customerName, email, reference, phone pe.
page default 1, minimum 1.
limit default 10, 1 se 50.
sort default createdAt. Allowed: date, startTime, createdAt, customerName, reference, status, email.
order asc ya desc. Default desc, yani naya pehle.
Sort object mein _id bhi hai, taaki same value pe order stable rahe.
date sort karte time startTime bhi usi direction mein sort hota hai.
startTime sort karte time date bhi saath sort hota hai.
Return { filter, page, limit, sort }.


server/src/models/Appointment.js
--------------------------------

Mongoose schema. Collection appointments.

Fields
reference      unique string, jaise HL-E9NRRC
serviceId      consultation | demo | support
serviceName    Consultation | Demo | Support
date           "2026-10-15"
startTime      "12:00"
endTime        "12:30"
customerName
email          save se pehle lower case aur trim
phone          10 digit string
status         confirmed ya cancelled, default confirmed
cancelledAt    Date ya null
createdAt, updatedAt  timestamps: true se khud bante hain

Unique index
{ serviceId, date, startTime } unique hai, lekin sirf jahan status confirmed hai.
Yeh partial index hai. Do confirmed rows same service, same din, same start nahi le sakte.
Cancelled row index se bahar ho jati hai, isliye wahi time dubara book ho sakta hai.
Alag service same time le sakti hai, kyunki serviceId index ka hissa hai.

Doosra index { email, date } visitor ki list tez dhundhne ke liye hai.
reference pe unique pehle se schema mein hai.

toJSON
_id ko id string bana deta hai aur _id hata deta hai.
__v nahi jaata. Client ko saaf object milta hai.

applyAvailability(date, takenStarts, now)
buildDaySlots se 16 slots leta hai.
Har slot ka state:
- past, agar isPastSlot true
- booked, agar woh start time confirmed bookings ke Set mein hai
- open, baki

upcomingCount woh slots jin ka state past nahi.

availabilityMessage(availability)

fullyBooked: "This day is fully booked. Please try another date."

getAvailability(serviceId, date, now)

Cancelled bookings yahan nahi aati, isliye cancel ke baad slot open dikhta hai.

server/src/services/appointments.js
-----------------------------------

present(doc, now)
Mongo document ko JSON banata hai.
phase "upcoming" tab jab status confirmed hai aur hasEnded false hai.
Warna "closed". Cancelled hamesha closed.
canCancel true tab jab status confirmed hai. Past confirmed visit bhi cancel ho sakti hai, kyunki code status dekhta hai, time nahi.
Client isi phase se Upcoming aur Past cards banata hai.

isDuplicateKey(err)
Mongo duplicate key error code 11000 hai.
Kabhi error seedha code pe hota hai, kabhi cause.code pe. Dono check hain.

isReferenceClash(err)
11000 tab bhi aata hai jab reference unique index takra jaye.
keyPattern.reference ho, ya message mein "reference" ho, to yeh clash hai.
Slot wala clash alag hai. Usme serviceId, date, startTime hota hai.

insertOnce(payload)
Appointment.create.
11000 nahi hai to error aage throw.
Reference clash hai to null return. Caller naya reference try karega.
Slot clash hai to 409 SLOT_TAKEN: "That time was just booked. Please choose another."

insertAppointment(payload)
4 baar try. Har baar naya makeReference().
Koi insert success ho to woh document return.
4 baar reference clash ho to 500 "We could not finish the booking."
Itna rare hai, practical mein pehli try mein ban jata hai.

createAppointment(payload, options)
Abhi ka time options.now ya kolkataNow().
parseBooking body check karta hai. Galat form yahin 400 pe ruk jata hai.
getService se service ka naam lete hain.
isPastSlot true ho to 400 SLOT_PAST. "That time has already passed."
Phir Appointment.exists: same service, date, start, status confirmed.
Mil gaya to 409 SLOT_TAKEN. Yeh fast check hai.
Do requests ek saath is check ko pass kar sakti hain.
Asli lock unique index hai. insertAppointment ke andar insertOnce dusri request ko 409 de deta hai.
Save hone wale fields: service, date, start, end, name, email, phone, status confirmed.
Reference insertAppointment khud lagata hai.
Return { appointment: present(...) }.

listAppointments(filter, options)
Appointment.find(filter). Filter mein email hota hai, isliye sirf usi aadmi ki rows.
present karke sort:
upcoming pehle, closed baad mein.
Phir date, phir startTime.
Return array. Controller ise { appointments } mein wrap karta hai.

listAdminAppointments(query, options)
filter, page, limit, sort parseAdminListQuery se aate hain.
countDocuments aur find ek saath Promise.all se.
skip (page - 1) * limit, phir limit.
Return { appointments, page, limit, total, pages }.

bookedEmail(value)
Trim, lower case. Email pattern na ho to 400 "Enter the email you booked with."
Get aur cancel dono isi se email maangte hain.

getAppointment(id, options)
Email bookedEmail se.
id valid ObjectId na ho to 404. Galat id pe 500 nahi chahiye.
findOne({ _id, email }). Email match na ho to bhi 404.
Isse koi doosre ki appointment id guess karke nahi khol sakta.
Return present(doc).

cancelAppointment(id, options)
Email aur id check.
findOneAndUpdate sirf tab chalega jab _id, status confirmed, aur email teeno match kare.
$set status cancelled aur cancelledAt abhi ka time.
{ new: true } updated document deta hai.
Update nahi hua to dobara find:
document hi nahi ya email alag hai to 404.
document hai par confirmed nahi to 409 ALREADY_CANCELLED.
Success pe { appointment: present(...) }.
Status cancelled hote hi row partial unique index se nikal jati hai. Slot khul jata hai.
Row delete nahi hoti. List mein cancelled dikhti rehti hai.

Jo code interviewer ko dikhana hai
-----------------------------------

Double booking
Model ka partial unique index, aur appointments.js mein exists check ke baad insertOnce.
Check pehle hai, lock index hai. 11000 ko SLOT_TAKEN banaya jata hai.
Reference wala 11000 alag handle hota hai, 4 retry.

Cancel ke baad slot
Status cancelled. Partial index sirf confirmed rows pakadta hai.
getAvailability bhi sirf confirmed padhti hai.

Sirf apni appointments
parseListQuery email ke bina 400.
get aur cancel find mein email lagate hain. Match na ho to 404.

Past slot
dateProblem purana din rokta hai.
isPastSlot aaj ka shuru ho chuka slot rokta hai.
createAppointment booking se pehle yeh dobara check karta hai.
